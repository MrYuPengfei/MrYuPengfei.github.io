Jami JAMS (Java 版) 容器化部署指南本指南详细介绍了如何在 Windows 11 环境下，利用官方源码构建 jams:v3.8 镜像，并实现 Docker Compose 与 Kubernetes 的部署。1. 源码获取与镜像构建基于官方 Java 开发架构，利用项目自带的 Dockerfile 进行多阶段构建。1.1 获取源码# 克隆官方 Git 仓库 git clone https://git.jami.net/savoirfairelinux/jami-jams.git cd jami-jams 参考资料: Jami JAMS Git Repository1.2 构建镜像# 使用官方 Dockerfile 构建并标记 docker build -t jams:v3.8 . 参考资料: JAMS Documentation - Building from source2. Docker Compose 本地验证方案适用于开发阶段的快速联调，验证 JAMS 启动参数及 LDAP 连通性。2.1 准备自签名证书JAMS 强制要求 SSL 证书才能启动 Web 管理界面。mkdir certs openssl req -x509 -newkey rsa:4096 -keyout certs/key.pem -out certs/cert.pem -sha256 -days 365 -nodes -subj “/CN=localhost” 2.2 编写 docker-compose.ymlservices: openldap: image: osixia/openldap:1.4.0-amd64 container_name: openldap environment:

  • LDAP_ORGANISATION=Jami
  • LDAP_DOMAIN=jami.net
  • LDAP_ADMIN_PASSWORD=admin123 ports:
  • “389:389”

jams: image: jams:v3.8 container_name: jams ports:

  • “8443:8443” environment:
  • JAMS_PORT=8443
  • SSL_CERT=/opt/jams/certs/cert.pem
  • SSL_KEY=/opt/jams/certs/key.pem volumes:
  • ./certs:/opt/jams/certs:ro # 挂载本地证书目录到容器 depends_on:
  • openldap 参考资料: Docker Compose File Reference & Osixia OpenLDAP README3. Kubernetes 详细部署方案适用于生产环境或需要容器编排能力的场景。3.1 创建 Kubernetes Secretkubectl create secret generic jams-certs
    –from-file=cert.pem=certs/cert.pem
    –from-file=key.pem=certs/key.pem 3.2 编写资源清单 jams-k8s.yaml# 1. OpenLDAP 部署 apiVersion: apps/v1 kind: Deployment metadata: name: openldap spec: selector: matchLabels: app: openldap template: metadata: labels: app: openldap spec: containers:
  • name: openldap image: osixia/openldap:1.4.0-amd64 env:
  • name: LDAP_ORGANISATION value: “Jami”
  • name: LDAP_DOMAIN value: “jami.net”
  • name: LDAP_ADMIN_PASSWORD value: “admin123”

apiVersion: v1 kind: Service metadata: name: openldap spec: ports:

  • port: 389 selector: app: openldap

2. JAMS 部署

apiVersion: apps/v1 kind: Deployment metadata: name: jams spec: selector: matchLabels: app: jams template: metadata: labels: app: jams spec: containers:

  • name: jams image: jams:v3.8 imagePullPolicy: Never # 强制使用本地构建的镜像 env:
  • name: JAMS_PORT value: “8443”
  • name: SSL_CERT value: “/opt/jams/certs/cert.pem”
  • name: SSL_KEY value: “/opt/jams/certs/key.pem” ports:
  • containerPort: 8443 volumeMounts:
  • name: cert-vol mountPath: /opt/jams/certs readOnly: true volumes:
  • name: cert-vol secret: secretName: jams-certs

apiVersion: v1 kind: Service metadata: name: jams-service spec: type: LoadBalancer ports:

  • port: 8443 targetPort: 8443 selector: app: jams 参考资料: Kubernetes Secrets Documentation4. 方案优劣对比分析特性Docker ComposeKubernetes (K8s)优势配置极简，适合本地单机测试，资源开销小。高可用自愈，支持滚动更新，适合多节点集群。劣势缺乏自动扩缩容与健康检查重启机制。学习成本高，网络与存储配置相对复杂。参考来源Docker Compose vs K8s5. 核心注意事项 (深度检查清单)5.1 端口映射检查容器内端口: JAMS 内部通过环境变量 JAMS_PORT 监听。必须确保 targetPort 也是 8443。参考资料: JAMS Launcher Parameters5.2 卷挂载路径一致性核对: SSL_CERT 环境变量指向的值必须等于 mountPath + Secret 文件名。示例: /opt/jams/certs (mountPath) + cert.pem (Secret Key) = /opt/jams/certs/cert.pem。5.3 镜像拉取策略注意: 在 Windows Docker Desktop 上部署本地构建镜像，务必将 imagePullPolicy 设为 Never。参考资料: K8s Image Pull Policies5.4 LDAP 连通性地址: 在 JAMS Web 引导界面中，LDAP Server 应填入 ldap://openldap:389。
