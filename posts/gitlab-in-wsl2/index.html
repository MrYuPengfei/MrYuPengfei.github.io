Run Gitlab in WSL2 Ubuntu24.04

January 5, 2026

踩坑

如果WSL2有多个ubuntu，如ubuntu22和ubunut24，只要有一个主机占用了gitlab所需要的端口，就不能正常使用gitlab。

✅ Ubuntu24.04 WSL2 部署GitLab「HTTPS+百度云120.48.161.177」完整版（生产标准）

🎯 核心适配 & 痛点解决

✅ 完美适配 WSL2无固定公网IP、无固定本地IP 核心痛点（全网最优穿透方案，永久稳定）； ✅ 百度云服务器 120.48.161.177 作为唯一公网入口，部署Nginx反向代理+HTTPS终结，符合生产标准； ✅ 全程无需关心WSL2 IP变化，IP动态漂移不影响公网访问，32GB内存满配GitLab全功能； ✅ 所有命令可直接复制执行，零手动配置冗余，部署完成后支持「Web访问+SSH代码推拉+CI/CD+镜像仓库」全功能。

🎯 核心架构（生产级稳定，彻底解决IP问题）

✅ 这是适配WSL2动态IP的最优架构，无端口转发失效、无IP漂移问题，可长期运行

公网用户 → 百度云服务器(120.48.161.177)【Nginx反向代理+HTTPS证书】 → 永久SSH反向隧道 → WSL2 Ubuntu24【GitLab全功能运行】

架构分工（各司其职，极简高效）

🖥️ WSL2 Ubuntu24：运行GitLab本体（32GB内存满配，启用CI/CD/Registry/监控），数据100%本地可控； ☁️ 百度云120.48.161.177：① 公网IP+域名入口 ② Nginx反向代理+HTTPS证书 ③ 接收SSH隧道流量，仅做转发（512MB内存即可）； 🔗 永久SSH反向隧道：核心！打通WSL2 ↔ 百度云服务器，无视WSL2 IP动态变化，隧道断连自动重连，生产级稳定。

🚨 前置必做（3步，缺一不可，生产基础）

✅ 一、WSL2 Ubuntu24 环境初始化（本地，解决所有依赖/冲突）

在WSL2终端执行，完成系统配置、依赖安装、冲突修复，适配GitLab DEB部署+32GB内存：

# 1. 系统全量更新+部署必备依赖（Ubuntu24 noble专属）
sudo apt update && sudo apt full-upgrade -y && sudo apt install -y curl wget vim openssh-server ca-certificates tzdata lsb-release apt-transport-https cron

# 2. 修复containerd冲突（Ubuntu24专属坑，必做！）
sudo apt remove -y containerd runc && sudo apt autoremove -y && sudo apt --fix-broken install -y

# 3. 安装Docker（GitLab CI/CD/Registry必备）+ 授权
sudo apt install -y docker.io docker-compose-plugin containerd.io
sudo systemctl enable --now docker && sudo usermod -aG docker $USER && newgrp docker

# 4. 验证Docker可用（无报错即成功）
docker run --rm hello-world

✅ 二、百度云服务器「120.48.161.177」前置配置（云端，优先级最高）

在百度云服务器终端执行，完成安全组放行、软件安装，为代理/隧道做准备：

✔️ 1. 安全组端口放行（控制台操作，必做）

登录百度云控制台 → 实例120.48.161.177 → 安全组 → 配置规则，添加以下TCP规则，来源均为0.0.0.0/0： ✅ 必放端口：80(HTTP)、443(HTTPS)、22(SSH)、2222(GitLab代码)、5000(镜像仓库)； ✅ 辅助端口：2200(SSH隧道备用)（防止22端口冲突）。

✔️ 2. 云端软件安装（Nginx+SSH优化，直接复制）

# 1. 安装Nginx（反向代理核心）+ 证书工具（HTTPS必备）
sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx

# 2. 优化SSH配置（允许反向隧道，永久生效）
sudo sed -i 's/#GatewayPorts no/GatewayPorts yes/' /etc/ssh/sshd_config
sudo sed -i 's/#PermitTunnel no/PermitTunnel yes/' /etc/ssh/sshd_config
sudo systemctl restart sshd && sudo systemctl enable --now nginx

✅ 三、域名解析（生产必备，HTTPS基础，必做）

登录你的域名管理平台（阿里云/腾讯云/华为云），添加A记录，将域名指向百度云固定IP：

✅ 主机记录：gitlab（示例：最终访问域名 gitlab.xxx.com）； ✅ 记录值：120.48.161.177（固定不变）； ✅ TTL值：10分钟（快速生效）。 ⚠️ 验证解析：本地执行 ping gitlab.xxx.com，返回120.48.161.177即生效。

✅ 步骤1：WSL2 Ubuntu24 部署GitLab（32GB内存满配，HTTPS模式）

全程在WSL2终端执行，无需指定WSL2 IP，适配动态IP环境，启用GitLab全功能，符合生产标准：

1.1 配置GitLab官方DEB源（Ubuntu24 noble专属）

# 导入GPG密钥
curl -fsSL https://packages.gitlab.com/gitlab/gitlab-ce/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/gitlab-ce-archive-keyring.gpg
# 写入noble版本源配置（24.04唯一适配）
echo "deb [signed-by=/usr/share/keyrings/gitlab-ce-archive-keyring.gpg] https://packages.gitlab.com/gitlab/gitlab-ce/ubuntu/ noble main" | sudo tee /etc/apt/sources.list.d/gitlab-ce.list
sudo apt update

1.2 安装GitLab（生产标准：强制HTTPS+监听所有IP）

# 核心命令：指定HTTPS协议，监听0.0.0.0（无视WSL2 IP变化）
sudo EXTERNAL_URL="https://gitlab.xxx.com" apt install -y gitlab-ce

✅ 关键说明：gitlab.xxx.com 替换为你的真实域名，GitLab会自动生成自签SSL证书，满足HTTPS基础需求，后续由百度云提供可信证书。

1.3 32GB内存满配配置（全功能启用，无需瘦身）

编辑GitLab主配置，强制监听所有IP、放开所有功能，适配动态IP+反向代理场景：

sudo vim /etc/gitlab/gitlab.rb

粘贴以下配置（覆盖核心参数，直接复制，无需修改）：

# 1. 基础配置：HTTPS域名+监听所有IP（核心，适配动态IP）
external_url "https://gitlab.xxx.com"
nginx['listen_addresses'] = ['0.0.0.0']
nginx['redirect_http_to_https'] = true  # 强制HTTPS
nginx['client_max_body_size'] = '10GB'  # 允许大文件上传

# 2. 32GB内存高性能配置（满配，启用所有核心服务）
puma['worker_processes'] = $(nproc)
puma['max_threads'] = 8
sidekiq['concurrency'] = 32
postgresql['shared_buffers'] = '8GB'
redis['maxmemory'] = '4GB'

# 3. 全功能启用（CI/CD+镜像仓库+监控，生产必备）
gitlab_ci['enable'] = true
registry['enable'] = true
registry['listen_addr'] = "0.0.0.0:5000"
prometheus_monitoring['enable'] = true
grafana['enable'] = true

# 4. SSH配置（代码推拉端口，适配云代理）
gitlab_rails['gitlab_shell_ssh_port'] = 2222

1.4 初始化GitLab+启动全服务（生产标准）

# 重载配置+启动服务（32GB内存下约5分钟，耐心等待）
sudo gitlab-ctl reconfigure && sudo gitlab-ctl start

# 验证服务状态（所有服务为run即成功）
sudo gitlab-ctl status

# 获取root初始密码（保存备用，登录必备）
sudo cat /etc/gitlab/initial_root_password

1.5 本地验证GitLab可用（WSL2内）

# 本地访问测试，无报错即成功
curl -k https://127.0.0.1

✅ curl -k 忽略自签证书警告，返回GitLab网页源码即服务正常。

✅ 步骤2：建立「永久SSH反向隧道」（核心！解决WSL2动态IP）

🎯 核心价值

✅ 无视WSL2本地IP/公网IP变化，隧道永久稳定，断连自动重连； ✅ 无需端口转发、无需路由器配置，穿透所有NAT/防火墙限制； ✅ 生产级方案，WSL2重启、Windows重启后，隧道自动恢复。

2.1 第一步：WSL2免密登录百度云服务器（隧道基础，必做）

在WSL2终端执行，实现无密码SSH连接百度云120.48.161.177，避免隧道认证失败：

# 1. 生成SSH密钥（一路回车，无需密码）
ssh-keygen -t rsa -b 4096

# 2. 推送公钥到百度云服务器（免密登录核心）
ssh-copy-id root@120.48.161.177

# 3. 验证免密登录（无需输入密码即成功）
ssh root@120.48.161.177 "echo 免密登录成功"

2.2 第二步：创建「隧道守护服务」（永久运行，断连自启）

在WSL2终端执行，将隧道注册为systemd服务，实现开机自启、异常重启，生产级稳定：

✔️ 2.2.1 创建隧道服务文件

sudo vim /etc/systemd/system/gitlab-tunnel.service

粘贴以下配置（直接复制，无需修改）：

[Unit]
Description=GitLab WSL2 → 百度云反向隧道
After=network-online.target sshd.service gitlab-runsvdir.service
Wants=network-online.target

[Service]
Type=simple
User=root
# 核心隧道命令：转发GitLab所有端口到百度云服务器
ExecStart=/usr/bin/ssh -CNg \
-R 80:127.0.0.1:80 \
-R 443:127.0.0.1:443 \
-R 2222:127.0.0.1:2222 \
-R 5000:127.0.0.1:5000 \
root@120.48.161.177
Restart=always
RestartSec=5  # 断连后5秒自动重连
TimeoutSec=0

[Install]
WantedBy=multi-user.target

✅ 命令说明：-R 端口:本机IP:本机端口 → 将百度云服务器端口，反向映射到WSL2对应端口，所有流量直达GitLab。

✔️ 2.2.2 启动并开机自启隧道服务

# 重载服务+启动隧道+开机自启
sudo systemctl daemon-reload
sudo systemctl enable --now gitlab-tunnel.service

# 验证隧道状态（显示active(running)即成功）
sudo systemctl status gitlab-tunnel.service

✅ 验证成功：百度云服务器执行 netstat -tulpn，能看到80/443/2222/5000端口处于LISTEN状态。

✅ 步骤3：百度云120.48.161.177 配置Nginx反向代理（HTTPS生产标准）

全程在百度云服务器终端执行，实现「域名+HTTPS+流量转发」，这是公网访问的唯一入口，符合生产安全规范。

3.1 备份默认配置+创建GitLab专属代理配置

# 备份默认配置，避免冲突
sudo rm -rf /etc/nginx/sites-enabled/default
sudo vim /etc/nginx/sites-available/gitlab-proxy.conf

3.2 粘贴生产级Nginx配置（直接复制，替换域名即可）

# ========== 生产标准：HTTPS+域名 核心配置（替换gitlab.xxx.com为你的域名） ==========
server {
    listen 443 ssl;
    server_name gitlab.xxx.com;

    # SSL优化（生产级，禁用弱协议）
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers on;
    ssl_ciphers EECDH+AESGCM:EDH+AESGCM:AES256+EECDH:AES256+EDH;
    ssl_session_cache shared:SSL:10m;

    # 核心转发规则：流量直达本地GitLab（隧道已映射，直接用127.0.0.1）
    location / {
        proxy_pass https://127.0.0.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_ssl_verify off;  # 信任WSL2自签证书（内部转发，安全）
    }
}

# ========== HTTP自动跳转HTTPS（生产必备，强制加密） ==========
server {
    listen 80;
    server_name gitlab.xxx.com;
    return 301 https://$host$request_uri;
}

# ========== SSH/镜像仓库端口转发（Stream模块，全功能支持） ==========
stream {
    # GitLab SSH代码推拉（2222端口）
    server { listen 2222; proxy_pass 127.0.0.1:2222; }
    # 镜像仓库Registry（5000端口）
    server { listen 5000; proxy_pass 127.0.0.1:5000; }
}

3.3 启用配置+申请Let’s Encrypt可信证书（生产核心）

# 1. 启用配置+检测语法（无报错则继续）
sudo ln -s /etc/nginx/sites-available/gitlab-proxy.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl restart nginx

# 2. 一键申请免费HTTPS可信证书（消除浏览器警告，生产必做）
sudo certbot --nginx -d gitlab.xxx.com

# 3. 启用证书自动续签（有效期90天，永久生效）
sudo certbot renew --dry-run

✅ 成功标志：执行后提示「Successfully received certificate」，证书自动配置到Nginx。

✅ 步骤4：公网访问验证（生产标准，全功能测试）

✅ 4.1 Web访问验证（核心）

浏览器输入生产标准地址：https://gitlab.xxx.com ✅ 效果：直接进入GitLab登录页，无任何安全警告（HTTPS证书可信）； ✅ 登录：用户名root + 步骤1中获取的初始密码，登录后立即修改新密码。

✅ 4.2 SSH代码推拉验证（生产必备）

本地电脑终端执行，测试代码克隆/推送功能：

# 克隆测试项目（替换为你的项目路径）
git clone ssh://git@gitlab.xxx.com:2222/root/test-project.git

# 推送测试代码（正常无卡顿）
cd test-project && echo "prod test" > README.md
git add . && git commit -m "prod init" && git push origin main

✅ 4.3 CI/CD+镜像仓库验证（全功能）

  1. CI/CD流水线：新建项目添加.gitlab-ci.yml，提交后查看流水线正常运行；
  2. 镜像仓库推送： 
    docker login gitlab.xxx.com:5000 -u root -p 你的GitLab密码
docker tag hello-world:latest gitlab.xxx.com:5000/root/test-project/hello:v1
docker push gitlab.xxx.com:5000/root/test-project/hello:v1

✅ 生产级运维必备（故障兜底+优化，必做）

🎯 一、WSL2端：GitLab/隧道故障快速恢复

# 1. GitLab服务异常重启
sudo gitlab-ctl restart

# 2. 隧道服务异常重启
sudo systemctl restart gitlab-tunnel.service

# 3. 查看隧道日志（排查断连问题）
sudo journalctl -fu gitlab-tunnel.service

# 4. GitLab定时备份（数据本地保存，生产必备）
sudo gitlab-rake gitlab:backup:create

🎯 二、百度云端：Nginx/证书故障恢复

# 1. Nginx配置检测+重启
sudo nginx -t && sudo systemctl restart nginx

# 2. 证书续签失败修复
sudo certbot renew --force-renewal

# 3. 查看Nginx日志（排查访问报错）
sudo tail -f /var/log/nginx/error.log

🎯 三、WSL2 IP漂移无感知兜底

✅ 本方案无需处理WSL2 IP变化，隧道默认映射127.0.0.1，即使WSL2重启IP改变，隧道自动重连，公网访问不受任何影响。

🚨 专属避坑指南（生产级，100%踩坑率）

❌ 坑1：隧道服务启动失败 → Connection refused

✅ 解决：确认WSL2免密登录百度云成功，执行 ssh root@120.48.161.177 验证，重新推送公钥。

❌ 坑2：公网访问502 → 隧道未映射端口

✅ 解决：WSL2执行 sudo systemctl restart gitlab-tunnel.service，百度云执行 netstat -tulpn | grep 443 确认端口监听。

❌ 坑3：HTTPS证书警告 → 解析未生效

✅ 解决：等待域名解析生效（10分钟），重新执行 sudo certbot renew。

❌ 坑4：CI/CD任务失败 → Docker权限问题

✅ 解决：WSL2执行 sudo usermod -aG docker gitlab-runner && sudo systemctl restart gitlab-runner。

✅ 本方案完美实现 Ubuntu24.04 WSL2（动态IP）→ GitLab（32GB满配）→ 百度云120.48.161.177（Nginx+HTTPS） 生产部署； ✅ 核心突破：SSH反向隧道 彻底解决WSL2无固定IP痛点，IP漂移无感知，隧道永久稳定； ✅ 生产合规：HTTPS可信证书、域名访问、全功能启用，满足企业级使用要求； ✅ 性能拉满：32GB内存支撑50-100人团队高并发，代码推拉/CI/CD/镜像仓库无压力。
